# Новый проект на OpenFOAM-12 (например, CFB-котёл): что перенести из CFD-Venturi

Документ для Claude, который начинает новый проект с тем же пользователем. В нём то, что не зависит от скруббера: пользователь, его система, установка OpenFOAM в облачном контейнере, проверенные стартовые точки для CFB и грабли, на которые мы уже наступили.

Вместе с этим файлом в новый репозиторий копируется **`tools/setup_openfoam12.sh`**: он не зависит от проекта.

---

## 0. Быстрый старт нового чата

1. Прочитать этот файл целиком.
2. Запустить установку OpenFOAM в фоне (Bash с `run_in_background: true`, `timeout` 7 200 000 мс):
   ```bash
   bash tools/setup_openfoam12.sh > /tmp/setup_openfoam12.log 2>&1
   ```
   Готово, когда в логе есть строка `check finished` и нет строк `MISSING`. Пока ставится, отвечать пользователю по документам.
3. Окружение в каждой команде: `source /opt/of12env.sh`.
4. Справка по устройству кейсов, скриптов и пост-обработки — репозиторий `razorsee-ee/CFD-Venturi` (ветка `claude/hopeful-noether-1zya1a`), его можно подключить через `add_repo` только на чтение. Полная история того проекта — `docs/HANDOFF.md` там.

## 1. Пользователь и как с ним работать

- Общается **по-русски**, коротко, иногда с опечатками. Инженер-практик: эксплуатирует установку пиролиза; знает процесс лучше модели.
- Раньше работал во FreeCAD + CfdOF. Чистый OpenFOAM и ParaView осваивает по ходу. ParaView объяснять пошагово: где кнопка, что выбрать.
- **Что он ждёт:**
  - готовые команды для терминала **MSYS2**, **каждая команда в отдельном блоке `bash`**;
  - короткое объяснение, что происходит и на что смотреть;
  - честность: что не проверено — так и сказать.
- **Что присылает:** скриншоты графиков и ParaView, `tail` логов, небольшие текстовые файлы.
- **Пожелания:**
  - беречь токены: длинные логи просить файлом или `tail`;
  - **сначала проверять у себя** на грубой сетке, потом давать ему: он не любит гонять расчёт впустую;
  - «пока ничего не считай, рассуждаем» — значит только рассуждать;
  - физическая правдоподобность важнее красивой картинки: если результат противоречит практике установки, он так и скажет.
- Код он забирает через `git pull`: после каждого законченного шага — коммит и пуш в рабочую ветку.

### 2.1 Особенности Windows/blueCFD (уже наступили, учитывать с первого дня)

| # | Проблема | Что делать |
|---|---|---|
| 1 | **`:` в именах файлов запрещён.** Поля вида `cloud:...` не видны ни ParaView, ни `foamPostProcess` | не строить на них ничего для пользователя; нужное поле копировать/пересчитывать в имя без `:` или писать свой VTK |
| 2 | Кодировка консоли и файлов **cp1252** → `UnicodeEncodeError` на кириллице и «м²» | в Python везде `encoding="utf-8"` и `sys.stdout.reconfigure(encoding="utf-8")` |
| 3 | Окно matplotlib (GTK3Agg) под MSYS **не перерисовывается** | графики писать в png + html со своим автообновлением; открывать `explorer.exe "$(cygpath -w file.html)"` |
| 4 | snappyHexMesh на Windows даёт **чуть другую сетку**, чем Linux | в `meshQualityDict` `minTetQuality 1e-15`; иначе частицы сыпали `No base point for face` и расчёт полз в десятки раз медленнее |
| 5 | Запись огромных логов (тысячи предупреждений) очень медленная | следить, чтобы лог не забивался предупреждениями |
| 6 | **CRLF**: Windows-git ставит `\r`, `./Allrun` падает | в корне репозитория `.gitattributes` с `* text=auto eol=lf` |
| 7 | `foamDictionary -set` переформатирует весь файл → у пользователя конфликтует `git pull` | менять значения в `system/*` через `sed` (хелперы `bin.sh` в CFD-Venturi); после `Allclean` файлы побайтово совпадают с git |
| 8 | `/proc/cpuinfo` в MSYS врёт про ядра | верить PowerShell: `Get-CimInstance Win32_Processor` |
| 9 | Остановить зависший решатель | `tasklist \| grep -i foamRun`, затем `taskkill //F //IM foamRun.exe` |

## 3. Облачный контейнер Claude

### 3.1 Установка OpenFOAM-12 (`tools/setup_openfoam12.sh`)

- **Путь 1 — готовый пакет**, несколько минут. Нужен хост `dl.openfoam.org` в разрешённых хостах окружения. В окружении **Default** пользователя он уже разрешён (ноябрь 2026).
  - Подвох: `dl.openfoam.org` отдаёт `.deb` перенаправлением на `http://downloads.sourceforge.net`, и apt такой переход https → http запрещает (`Redirection from https to 'http://...' is forbidden`).
  - Поэтому скрипт берёт из подписанного индекса apt URL и MD5 пакета, качает тот же файл с SourceForge **по https**, сверяет MD5 и ставит `apt-get install ./openfoam12_*.deb`. Остальные зависимости — из обычных зеркал Ubuntu.
  - **Проверено:** загрузка и сверка MD5 (OK). **Не проверено:** сама установка `.deb` — в прошлой сессии её заблокировала система безопасности сессии. Если это повторится, скрипт сам уходит на путь 2; ускорить можно, попросив у пользователя разрешения.
- **Путь 2 — сборка из исходников** GitHub в `/opt/OpenFOAM-12`: **проверено**, ~1 ч на 4 ядрах. Важная деталь: в свежем контейнере пустые списки пакетов, перед `apt-get install` нужен `apt-get update` (без него «Unable to locate package»).
- Скрипт идемпотентен: перезапуск пропускает сделанное. В конце пишет `/opt/of12env.sh` и проверяет утилиты и библиотеки решателей (`lagrangianParcel`, `multiphaseEuler`, `incompressibleDenseParticleFluid`, `multicomponentFluid`).
- `/opt/of12env.sh` уже содержит `OMPI_ALLOW_RUN_AS_ROOT=1 OMPI_ALLOW_RUN_AS_ROOT_CONFIRM=1` — без них `mpirun` от root не стартует.

### 3.2 Правила работы в контейнере

- 4 ядра: в копии кейса `numberOfSubdomains 4`.
- Проверочные прогоны — в копии кейса в scratchpad; результаты прогонов в репозиторий не коммитить, только эталонные картинки в `docs/`.
- Долгие расчёты: Bash с `run_in_background: true` и явным `timeout` (до 7 200 000 мс), ждать уведомления, **не опрашивать `sleep`**. Без этого длинная команда уходила в авто-фон и убивалась через 30 мин.
- **Не использовать `pkill -f`/`pgrep -f`** с шаблоном, который встречается в собственной командной строке — команда убивает сама себя. Останавливать по PID или `pkill -x <точное имя>`.
- Окна графиков в контейнере не нужны (`pkill -x python3`, если скрипт кейса их запустил).

## 4. Стартовые точки для CFB в OpenFOAM-12

В OF-12 решатели — модули `foamRun` (`solver <модуль>` в `controlDict`). Туториалы: `$FOAM_TUTORIALS`.

| Подход | Модуль | Туториал | Проверено здесь |
|---|---|---|---|
| Эйлер–Эйлер (две сплошные фазы, кинетическая теория гранулированной среды, `Theta.particles`) | `multiphaseEuler` | `multiphaseEuler/fluidisedBed` (и `fluidisedBedLaminar`) | **да**: `./Allrun` на 4 процессах, `endTime 0.05` ≈ 13 с |
| MPPIC (частицы-посылки в плотном слое) | `incompressibleDenseParticleFluid` | `incompressibleDenseParticleFluid/GoldschmidtMPPIC`, также `cyclone`, `column`, `injectionChannel` | **да**: `blockMesh` + `foamRun`, `endTime 0.05` ≈ 11 с на 1 ядре, 24 750 посылок |
| Горение угля частицами (облако с химией) | `multicomponentFluid` | `multicomponentFluid/simplifiedSiwek` | нет |

Что важно для котла (проверить по исходникам и туториалам, прежде чем обещать пользователю):
- `incompressibleDenseParticleFluid` — **несжимаемый и без уравнения энергии**: годится для гидродинамики слоя, циркуляции и циклона, но не для теплообмена и горения.
- `multiphaseEuler` поддерживает теплообмен между фазами и с газом; для слоя это основной кандидат, если нужна температура.
- В `GoldschmidtMPPIC` нет `Allrun`: запуск `blockMesh` и `foamRun`.

## 5. Перенесённые уроки по численной части

Это опыт стационарных сжимаемых расчётов в CFD-Venturi; для CFB (обычно нестационарного) проверять заново, но знать заранее полезно.

| Урок | Подробности |
|---|---|
| Стационарный сжимаемый расчёт расходится с первой итерации | релаксация плотности `fvSolution/relaxationFactors/fields/rho 0.05` |
| Закрученный поток качался ±50 кПа | SIMPLEC: `PIMPLE/consistent yes`, `fields/p 1` |
| Облако частиц обрывается через 2 итерации | `residualControl` остановил расчёт: на этапе с частицами его выключать |
| Источники от частиц «взрывают» газ (U > 3000 м/с) в мелких ячейках у точки впрыска | впрыск не в самые мелкие ячейки, `semiImplicit 0.5` |
| Частицы застревают в вихре, пересчёт облака — часы | ограничить `maxTrackTime` |
| Последняя итерация этапа не записалась | длина этапа должна делиться на `writeInterval` |
| Расход на входе «уплывает» при росте плотности | задавать массовый расход (`flowRateInletVelocity`/`swirlFlowRateInletVelocity` с `massFlowRate`), а не скорость |
| `checkMesh -allGeometry` пугает «вогнутыми ячейками» snappy | пользователю давать простой `checkMesh` |
| Патч `wall` конфликтует с группой `wall` | называть `walls` |

### 5.1 Удобства, которые пользователь уже знает (повторить в новом проекте)

Скрипты в каждом кейсе (образцы — в CFD-Venturi):

| Скрипт | Что делает |
|---|---|
| `Allrun` | сетка + расчёт |
| `Allclean` | очистка, возвращает правленные значения к git |
| `stop` | `stopAt writeNow` через sed: записать и выйти |
| `Allcontinue [N]` | продолжить, при N — ещё N шагов |
| `plot` | фоновый `plot_convergence.py --html`: png + html в браузере |
| `bin.sh` | sed-хелперы `setControl`, `residualControl on/off`, `latestTime` |

`runParallel`/`runApplication` пропускают шаг, если лог уже есть: для повтора старый лог удалять.
