# Состояние проекта (памятка для продолжения в новом чате)

- **Ветка:** `claude/hopeful-noether-1zya1a`, репозиторий `razorsee-ee/CFD-Venturi`.
- **Пользователь** общается по-русски. Опыт: FreeCAD + CfdOF; чистый OpenFOAM и ParaView осваивает по ходу.
- **Новому чату:** сначала **`docs/HANDOFF.md`** — подробное описание всего проекта и история решений; этот файл — краткая сводка. Окружение для проверочных расчётов: `bash tools/setup_cloud_env.sh`.

## 1. Задача
Скруббер Вентури (чертёж: `geometry/params.py`). Горячий пиролизный газ 76 т/ч при 470 °C, орошение тяжёлым маслом 32 т/ч при 100 °C от форсунки «трубка → отражательный диск ⌀65» на лансете перед горловиной.

**Главный вопрос пользователя:** где масло попадает на стенку и где возможен кокс. На практике отложения **всегда в горловине**, при любой ориентации форсунки.

## 2. Где считает пользователь
- **Система:** Windows, blueCFD-Core 2024 = OpenFOAM-12 (Foundation), MS-MPI, терминал MSYS2 (`$FOAM_RUN/CFD-Venturi`).
- **Компьютер:** i7-9700, 8 физических ядер, 16 ГБ; в `decomposeParDict` стоит 8.
- **Python** из MSYS2: пакеты ставятся через `pacman -S mingw-w64-x86_64-python-<pkg>`, pip нет. Нужны numpy и matplotlib.
- **Особенности Windows (уже обойдены, не ломать):**
  - имена файлов с `:` (`cloud:...`) не видны ни ParaView, ни foamPostProcess. Карта осаждения поэтому пишется как `VTK/walls_oil.vtk`;
  - текст в UTF-8: в `tools/*` явный `encoding`;
  - окно matplotlib не обновляется → `./plot` открывает в браузере `convergence.html`, который сам перезагружает `convergence.png`;
  - snappyHexMesh на Windows даёт немного другую сетку → `minTetQuality 1e-15` в `meshQualityDict`. Без этого капли сыпали предупреждения `No base point` и расчёт полз;
  - во время расчёта не делать `git checkout -- .`: он сбрасывает `controlDict` идущего расчёта.

## 4. Кейсы

| Папка | Область | Масло | Статус |
|---|---|---|---|
| `case/` | весь аппарат + 2 м удлинения; газ 600 итераций | `thermoCloud`: капли рождаются на кольце r = 50–150 мм за диском, d32 88 мкм | проверен; у пользователя посчитан **газ**, масло — со старыми свойствами |
| `case-throat/` | x = 1.75 м … диффузор + 0.6 м (+0.3 м удлинения); газ 200 итераций | как в `case`; облако брызг `splashCloud` есть, по умолчанию выключено | проверен; у пользователя считался |
| `case-rim/` | как `case-throat` | **`sprayCloud`**: капли ~1 мм с кромки диска (r 33–35 мм, 80–95°, 25 м/с), дробление Reitz–Diwakar; газ — смесь `pyroGas` + `oil` (пар, Y = 0), решатель `multicomponentFluid`; масло — `liquid` | проверен у меня; **пользователь посчитал** — 3.41 кПа и 391 °C совпали с моими |
| `case-rim-reverse/` | как `case-rim` | фланец развёрнут на 180° вокруг оси лансета: диск **против потока**, x 2.076–2.084, `direction (-1 0 0)` | **не прогонялся**; пользователь собирался запустить |

**Вход укороченных кейсов:**
- `swirlFlowRateInletVelocity`: точный расход 21.11 кг/с + W(r) из `constant/inletSwirl`;
- T, k, ω через `timeVaryingMappedFixedValue` из `constant/inletProfile`; `Allrun` копирует в `boundaryData`.

**Выход укороченных кейсов:** `fixedMean` p.

## 5. Физика и допущения
- **Газ.** Псевдокомпонент `pyroGas`: M 67.4, cp 2835, μ 1.82e-5, Pr 1.04, идеальный газ. Конденсации и испарения **нет** (массообмена нет вообще).
- **Вход полного кейса.** Сильная закрутка S = 0.6: твёрдое тело, ω = 84 рад/с, 37 м/с у стенки. Турбулентность 15 %. Причина: газ идёт из вихревой трубы циклона через колено ~2 м до скруббера.
- **Масло.** ρ 1150 (1.2 кг/л в холодном), 40 сСт при 100 °C (μ 46 мПа·с), σ 0.03 (принято), cp 1950. Корреляции дают d32 ≈ 88 мкм; в `case-rim` дробление само даёт ~90–100 мкм.
- **Капли на стенке:** `localInteraction`, все патчи `escape` → статистика по патчам. Плёнка не моделируется.
- **Стационарная постановка.** Облако пересчитывается каждые 10 итераций, `maxTrackTime 0.3` с в укороченных кейсах. Источники `semiImplicit 0.5`.

## 6. Критичные численные настройки (почему именно так)

| Где | Настройка | Почему |
|---|---|---|
| `fvSolution` | `rho 0.05` | без релаксации плотности стационарный сжимаемый расчёт расходится с первой итерации |
| `fvSolution` | `consistent yes` (SIMPLEC), `p 1` | с SIMPLE закрутка на сетке 0.65 качалась ±50 кПа |
| `fvSchemes` | `div(phi,U)` linearUpwindV | upwind съедал ~30 % закрутки; без закрутки нужно вернуть upwind |
| `controlDict` | `writeInterval 100` | газовые этапы 200/600 итераций должны быть кратны шагу записи |
| `meshQualityDict` | `minTetQuality 1e-15` | для трассировки капель |
| впрыск | не на кромке диска (в `thermoCloud`) | газ локально «взрывался», U > 3000 м/с |

## 8. Гипотезы отложений в горловине (модель их пока не содержит)
1. Плёнка масла со стенки стекает в горловину и перегревается.
2. Конденсация тяжёлых фракций из газа (мазут + тяжёлое масло — 2/3 массы газа) при смешении в горловине.
3. Удар пыли, сажи и смоляного тумана из циклона о мокрую стенку.

## 11. Как проверять расчёты в облачном контейнере Claude
- **Без готового OpenFOAM в окружении** его нужно собрать из исходников, ~2–3 ч на 4 ядрах:
  - `git clone https://github.com/OpenFOAM/OpenFOAM-12` и `ThirdParty-12` в `/opt`;
  - в `etc/bashrc`: `SCOTCH_TYPE=system`, `ParaView_TYPE=none`;
  - apt: `build-essential flex bison cmake zlib1g-dev libopenmpi-dev openmpi-bin libscotch-dev libptscotch-dev`;
  - `./Allwmake -j 4 -q`.
- **Быстрее:** в настройках окружения разрешить `dl.openfoam.org` и в setup script поставить пакет `openfoam12` → `/opt/openfoam12`.
- **mpirun от root:** `OMPI_ALLOW_RUN_AS_ROOT=1 OMPI_ALLOW_RUN_AS_ROOT_CONFIRM=1`.
- **Тест на 4 ядрах:** в копии кейса в scratchpad поставить `numberOfSubdomains 4`.
- **Осторожно:** не использовать `pkill -f` и `pgrep -f` с шаблоном, который встречается в собственной командной строке — убьёт свою же команду. Окно графиков завершать через `pkill -x python3`.
